# Slack Input Node

The **Slack Input Node** listens for Slack slash commands and for direct messages to your bot, and uses them to trigger your workflow. A direct message can carry files: text, images, PDFs and more (see [Direct Messages](#direct-messages)). It connects to your Slack workspace using Socket Mode, enabling real-time message handling without exposing a public HTTP endpoint.

![Slack Input Node](/img/nodes/slack-input-node-preview.webp)

## Prerequisites

Before using this node, you need to create and configure a Slack app. See the [Slack Bot Setup guide](../../getting-started/slack-bot-setup) for step-by-step instructions.

## Direct Messages

Besides the slash command, people can message the bot directly, from its **Messages** tab in Slack (the [Slack Bot Setup guide](../../getting-started/slack-bot-setup)'s manifest turns it on). A direct message triggers every running Slack Input node on the bot whose routing ID it names, or every one without a routing ID. Messages from bots and edits of earlier messages are ignored.

Files sent with a direct message reach the workflow too:

- **Text and code files** are added to the `message` in code blocks, each under its file name.
- **Images** are added to the `message` as data URLs, numbered in order (Image 1, Image 2, ...).
- **Other files** (PDF, Office documents, zip archives, videos, ...) are passed on as attachments in the node's `toolsPayload`, for tools such as the [Form Interaction Tool](/docs/nodes/ai/tools/form-interaction) to upload. The `message` names each one: `[Binary attachment: report.pdf]`.
- Each file can be up to **10 MB**, and a message's files up to **25 MB** together. A file past either limit is named in the `message` (`[Not included: ...]`) but left out. A file that can't be downloaded is left out too.

Downloading files needs the bot's `files:read` scope, which the setup guide's manifest includes. Files are downloaded from Slack only: a file shared from another service (a link to a Google Drive document, for example) is left out, so the bot token is never sent anywhere else.

## Output

When a matching slash command or direct message is received, the node passes the following data to connected downstream nodes:

<div className="fullWidthTable">

    | Field         | Type   | Description |
    |---------------|--------|-------------|
    | `channelId`   | string | The Slack channel (or direct message) the message came from |
    | `responseUrl` | string | URL to send a delayed response to the slash command (empty for a direct message) |
    | `userId`      | string | The Slack user ID who sent it |
    | `message`     | string | The text following the command (and routing ID); a direct message's files follow it |

</div>

The node's `toolsPayload` holds a direct message's other files, each as `{name, base64, mimeType}`; it is absent when there are none.

## Example Usage

For example usage, see the [Slack AI Web Search Bot Workflow](/docs/workflows/data/slack-ai-web-search-bot), which listens for Slack slash commands, queries the web with DuckDuckGo, and returns the AI-generated response directly in Slack.

## Common Use Cases

1. **AI-Powered Commands**: Trigger AI workflows directly from Slack.
2. **Team Automation**: Allow team members to run workflows without leaving Slack.
3. **Data Retrieval**: Fetch and return data in response to Slack commands.
4. **Multi-Workflow Routing**: Use different Routing IDs to run multiple independent workflows from the same bot.

## Best Practices

- **Always set a Routing ID** when running multiple Slack Input nodes to prevent accidental cross-triggering.
- **Keep tokens secure**: Store Bot and App tokens privately; never share them publicly.
- **Use Command Filter correctly**: Ensure it matches exactly the command registered in your Slack app manifest.
- **Combine with Slack Output Node**: Pair this node with the Slack Output Node to send responses back to users using the `responseUrl` output.

## Troubleshooting

### Common Issues

- **Node not receiving commands**: Verify the Bot Token, App Token, and Command Filter are all correctly configured. Ensure the Slack app is installed to your workspace and Socket Mode is enabled.
- **Routing ID mismatch**: Double-check that users include the correct routing ID in their command.
- **Token errors**: Confirm the Bot Token starts with `xoxb-` and the App Token starts with `xapp-`.
- **No direct messages arrive**: Check that the app's **Messages** tab is on and that it subscribes to the `message.im` event with the `im:history` scope (all in the setup guide's manifest); reinstall the app after changing scopes.
- **Files missing from a direct message**: The bot needs the `files:read` scope. Files over 10 MB, or past 25 MB for the whole message, are only named; files shared from other services are left out.
- **App disconnects**: Socket Mode connections may drop; the node reconnects by itself after 5 seconds.

### Performance Tips

- Use the Routing ID to isolate workflows and avoid processing unrelated commands.
- Pair with the **Slack Output Node** to provide immediate feedback to users.
