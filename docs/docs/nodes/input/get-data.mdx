# GET Data Node

The **GET Data Node** fetches data from any HTTP or HTTPS endpoint using a GET request. It is commonly used to retrieve JSON, text, or binary data from APIs or static URLs as the starting point for your workflow.

## Credentials in the URL

A key saved in [Settings → Credentials](/docs/getting-started/configuration#credentials) can go into the URL as `{{name}}`:

```
https://api.example.com/data?apikey={{myApiKey}}
```

- The value is filled in only to send the request, exactly as it is saved. If it holds characters such as `&` or spaces, save it URL-encoded. A whole URL saved as a credential works too: `{{myPrivateFeedUrl}}`.
- The node, the workflow file and the data passed between nodes keep `{{myApiKey}}`. Errors show the placeholder, not the value.
- If the name isn't saved, or the vault is locked, the node stops with an error that says which.
- Placeholders in a URL provided by an upstream node are filled in too.

:::caution
With **Provided by Upstream**, whatever builds the URL decides which key is sent and to which site: an LLM, a fetched page or an outside app could point `{{name}}` somewhere else. Use it only with sources you trust, and check workflows from others before running them.
:::

## Common Use Cases

1. **API Data Fetching**: Retrieve data from public or private APIs.
2. **Static File Download**: Download files or static resources.
3. **Workflow Trigger**: Start a workflow with external data.
4. **Data Integration**: Combine with other nodes for data transformation and visualization.

## Best Practices

- **Use correct data type**: Match the Data Type to the expected response for reliable parsing.
- **Validate URLs**: Ensure the URL is correct and accessible.
- **Handle errors**: Downstream nodes should handle possible fetch errors or missing data.
- **Secure endpoints**: Save API keys in Settings → Credentials and write `{{name}}` in the URL, so they stay out of workflow files.

## Troubleshooting

### Common Issues

- **Invalid URL**: Check for typos or missing protocol (`http://` or `https://`).
- **CORS errors**: Some APIs may block browser requests; use a proxy if needed.
- **Unexpected data format**: Ensure the Data Type matches the actual response.
- **Network errors**: Verify your internet connection and endpoint availability.
